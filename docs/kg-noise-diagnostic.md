## Actionable takeaways

**Person nodes (218,592 total) projected breakdown:**

- Usable clean persons: **~89,898** (41%)
- Recoverable via entity resolution: **~28,599** (13%)
- Extractor failure — requires pruning or pipeline fix: **~100,094** (46%)

**Priority fixes (in order of cost/benefit):**

1. **Scripture-reference filter** at NER stage — single regex rejects `Matthew 3:3`, `Alma 55:17`, `Jer 38:21` patterns that currently pollute `person`, `object`, `period`.
2. **Mojibake/HTML sanitization** at parser stage — UTF-8 decode errors (`ÏÎ¬`, `â`, `Â­`) and HTML fragments (`id="aside1_p1"`) should be stripped before NER.
3. **Spanish verb filter** — conjugated forms (`-aba`, `-ía`, `-aré`, gerunds) capitalized at sentence start are being promoted; add POS check or suffix blacklist.
4. **Entity resolution pass** on existing KG — canonicalize duplicates (`Lydia LYDIA`, `Amaleki` + `• Amaleki`), strip possessives, unify transliterations. Recovers cat 2 without reindexing.
5. **`object` type is critically noisy (~58%)** — review extractor rules for this type specifically before anything else; likely capturing raw tokens.
